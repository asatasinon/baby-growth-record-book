## 任务来源
- 前端、后端、测试和联调都依赖同一套 API 和数据契约。
- 当前已有设计文档和规格草案，但尚未整理成执行期的冻结基线和变更控制任务。

## 任务范围

### 负责范围
- 接口路径、请求响应字段、错误码、鉴权方式、分页与幂等约束。
- 实体、状态机、枚举值、关键领域约束。
- DDL 中的表结构、索引、唯一键、外键、检查约束。
- ID 与时间字段类型基线（`bigint` + UTC 毫秒时间戳）。
- ID 边界转换规则（出参字符串 ID、入参字符串 ID 转 `bigint`）。
- 文档间术语和字段命名的一致性校准。

### 不负责范围
- 前端页面交互实现。
- 核心业务逻辑编码实现。
- 汇总、提醒、AI、导出能力的实现细节。
- 上线验收执行。

## agent 接手说明
1. 接手前先检查 `T03` 的协作边界，确认当前 agent 只负责 `T04`。
2. 接手时先把“当前状态”改为 `进行中`，并在“交接记录”新增一条记录。
3. 所有设计、规格、DDL 调整必须先记录在本任务文档，再回写到 `docs/design/` 或 `docs/specs/`。
4. 如果需要修改 `T05` 至 `T10` 的内容，不直接越界，先在“外部依赖登记表”补充阻塞项。
5. 交付冻结结果后，把“当前状态”改为 `已完成`，并将未决项留在“外部依赖登记表”中。

## 可执行规范清单（ID 与时间戳）

| 规则编号 | 规则 | 执行动作 | 完成判定 |
| --- | --- | --- | --- |
| SPEC-ID-01 | OpenAPI 所有 `id/*_id` 为字符串并满足 `^[0-9]+$` | 检查 `S01` 中参数和 schema 字段 | 不存在未加正则的 ID 字段 |
| SPEC-ID-02 | 后端统一转换层处理 ID | 在 schema 层实现 validator/serializer，并禁止业务层散落转换 | 代码评审中无分散 `int(id_str)` |
| SPEC-ID-03 | 非法 ID 统一错误结构 | 返回 `INVALID_ARGUMENT` + `data.field/reason/value` | 接口样例和实际响应一致 |
| SPEC-TIME-01 | 时间字段统一毫秒时间戳 | `S01/S02/D03` 全量对齐为 `int64` 毫秒 | 无 ISO 时间字符串残留 |

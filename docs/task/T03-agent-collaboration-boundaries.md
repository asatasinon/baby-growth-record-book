## 任务背景
- `T01` 和 `T02` 已覆盖总体计划和验收清单，但仍偏全局视角。
- 多个 agent 并行执行时，如果没有稳定的任务边界，会出现同时修改同一模块、同一文档或同一验收项的问题。
- 需要通过“任务分片 + 文档归属 + 回写规则”来约束协作。

## 任务范围

### 本文档覆盖范围
- 定义任务分片原则。
- 定义每份细分任务文档的主责边界。
- 定义 agent 的允许修改范围、禁止越界范围和回写路径。
- 定义跨任务协作时的依赖交接方式。

### 本文档不覆盖范围
- 不替代各任务文档中的具体执行细节。
- 不替代产品、架构、设计、质量和规格本身的原始规则。
- 不定义具体代码实现方案。

## 任务拆解

### 分片原则
- 每个子任务文档只负责一个稳定能力域，不按临时人力拆分。
- 每个子任务文档必须能独立回答“做什么、依赖什么、完成后产出什么、由谁维护”。
- 同一类交付物只能有一个主责文档，不允许双主责。
- 总览类文档只做导航和状态汇总，不承载一线执行细节。

### Agent 执行规则

| 规则编号 | 规则 |
| --- | --- |
| R1 | agent 接任务时，必须只认领一份主任务文档，不允许同时作为两份文档的主执行者。 |
| R2 | agent 只能直接维护自己主责文档和该文档明确允许回写的索引文档。 |
| R3 | agent 如发现需要修改其他任务文档，必须先在自己文档中记录“外部依赖/阻塞”，不直接越界修改。 |
| R4 | agent 完成阶段性工作后，先更新本任务文档状态，再由总控 agent 同步汇总到 `T01/T02/T00`。 |
| R5 | 跨任务交接只能通过“输入已满足 / 输出已交付 / 阻塞未解除”三种状态进行，不通过口头约定替代。 |
| R6 | 如必须共同修改同一代码区域，应重新调整任务边界并先更新对应任务文档，再执行代码变更。 |

## 文档维护规则

### 允许直接维护的文档
- 主执行 agent：自己的主任务文档。
- 总控 agent：`T00`、`T01`、`T02`、`T03`。
- 任一 agent 在完成阶段节点后，可回写 `T00` 中的索引状态，但不应改写其他任务的细节内容。

### 禁止直接维护的文档
- 不允许修改其他子任务文档中的任务拆解、完成标准、状态跟踪和风险描述。
- 不允许在 `docs/product`、`docs/architecture`、`docs/design`、`docs/quality`、`docs/specs` 中写入任务型执行说明；执行说明应保留在 `docs/task/`。
- 不允许把跨任务公共规则分散写进多个子任务文档，公共规则统一回写到 `T03`。

### 回写顺序
1. 更新自己主责任务文档。
2. 如影响阶段总计划，更新 `T01`。
3. 如影响联调或验收条件，更新 `T02`。
4. 最后更新 `T00` 索引中的状态摘要。

## 角色分工

| 角色 | 主要职责 | 交付要求 |
| --- | --- | --- |
| 总控 agent | 负责任务分派、边界调整、总索引维护 | 不直接吞并子任务执行内容 |
| 执行 agent | 负责单一子任务文档下的实现和状态维护 | 保持边界清晰，不越权改写他人任务文档 |
| 评审人 | 对边界冲突、依赖是否满足进行审阅 | 发现冲突时先调边界再继续执行 |

## 依赖与阻塞

| 类型 | 内容 | 处理方式 |
| --- | --- | --- |
| 边界冲突 | 两份任务文档同时声称负责同一产物 | 立即回到 `T03` 修正归属 |
| 输入未就绪 | 上游文档未冻结或未交付 | 在下游文档登记阻塞，不自行替代冻结 |
| 索引失真 | 子任务状态与总览不一致 | 先以子任务文档为准，再更新 `T01/T02/T00` |

## 完成标准
- 所有执行类任务都已映射到唯一的主责文档。
- 任一 agent 在开始前都能判断自己是否有权修改某份文档。
- 总览文档与细分任务文档之间有明确的回写顺序。
- 新增任务时，可以依照本文档扩展，不破坏现有分片结构。

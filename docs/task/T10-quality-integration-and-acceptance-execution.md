## 任务背景
- 测试和验收不能只作为收尾清单存在，需要有单独的执行文档来承接联调节奏、测试数据、缺陷管理和验收结论。

## 任务范围

### 负责范围
- 测试计划、测试数据、关键场景和测试结果维护。
- 前后端联调推进和问题归集。
- 缺陷分级、回归验证和上线准入判断。
- 与部署、安全、恢复相关的验收消费。

### 不负责范围
- 业务实现细节维护。
- 规格冻结和字段语义决策。
- 部署和安全方案本身的制定。

## Agent 执行边界

### 允许维护
- 当前文档 `T10`
- `T02` 中与联调和验收结果直接相关的状态项

### 禁止越界
- 不改写 `T04` 至 `T09` 的任务拆解和完成标准。
- 不自行修改业务、部署和 AI 方案来“规避”缺陷。
- 不把测试结论写回产品、架构、设计文档。

## 预计输入
- `Q01` 定义的测试层级和关键场景。
- `T04` 至 `T09` 的各阶段可交付版本和阻塞说明。
- 测试环境、测试数据、凭证和恢复演练结果。
- 前后端和运维提供的联调窗口。

## 预计输出
- 联调计划和测试执行记录。
- 缺陷归属清单和回归结论。
- 发布前验收结论和上线建议。
- 回写到 `T02` 的联调与验收状态更新。

## agent 接手说明
1. 接手前确认本任务是联调和验收主文档，不负责业务方案制定。
2. 接手时先将“当前状态”改为 `进行中`，并记录当前负责的联调阶段。
3. 所有缺陷、回归、阻塞和验收结论都优先回写本任务文档。
4. 缺陷归属要按本任务文档中的归属规则分配，不直接改写其他任务文档的细节。
5. 交接时要写明已验证链路、未验证链路、阻塞缺陷和上线建议状态。

## 任务背景
- 运行环境、安全基线、备份恢复和发布材料都属于独立交付域。
- 如果这些事项分散在后端或测试任务文档中维护，很容易遗漏或被覆盖。

## 任务范围

### 负责范围
- `Docker Compose` 部署基线和环境变量模板。
- 健康检查、日志、对象存储、静态资源与 CDN 配置要求。
- HTTPS、日志脱敏、敏感信息保护、限流和最小权限要求落地。
- 数据备份、恢复演练和发布前材料准备。

### 不负责范围
- 业务功能实现。
- 页面联调和测试结论维护。
- AI 上下文和报表业务口径。

## Agent 执行边界

### 允许维护
- 当前文档 `T09`
- 与部署、安全、恢复和发布准备相关的运维说明

### 禁止越界
- 不改写 `T06/T07/T08` 的业务任务拆解。
- 不代替 `T10` 给出最终验收结论。
- 不修改产品和设计文档中的业务口径。

## 预计输入
- `A02` 的部署拓扑、环境变量和备份恢复要求。
- `A03` 的安全和隐私要求。
- `T06`、`T07`、`T08` 对运行环境和外部服务的需求。
- 发布窗口和验收节奏要求。

## 预计输出
- 可运行的 Compose 和网关配置基线。
- 安全检查清单和执行结果。
- 备份恢复演练记录。
- 发布准备就绪结论和阻塞项清单。

## agent 接手说明
1. 接手前确认本任务只负责环境、安全、恢复和发布准备，不维护业务逻辑。
2. 接手后先把“当前状态”改为 `进行中`，并写明当前处理的环境层级。
3. 所有部署模板、环境变量、安全检查项和恢复演练结果都先回写本任务文档。
4. 如发现业务实现缺失影响发布，登记外部依赖，不直接改写 `T06/T07/T08` 任务内容。
5. 交接时必须说明当前环境可用性、未完成安全项和发布阻塞项。

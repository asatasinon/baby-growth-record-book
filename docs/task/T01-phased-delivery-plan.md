## 任务来源
- 产品侧已明确多家庭育儿记录 SaaS 的目标形态、首版能力边界和阶段路线。
- 架构侧已明确采用 `Taro + React + TypeScript`、`FastAPI + SQLAlchemy + PostgreSQL`、`Docker Compose` 的模块化单体方案，并统一前端 `pnpm`、Python `uv` 依赖管理。
- 设计侧已给出页面树、关键业务流程、REST API、领域模型、数据库结构和 AI 规则边界。
- 质量侧已给出测试分层、关键场景、联调清单和上线验收标准。
- 规格侧已经沉淀 OpenAPI 与 DDL 草案，可作为研发实现和联调基线。

## 任务范围

### 本任务覆盖范围
- 完成从规格冻结到研发交付、联调测试、部署上线准备的全流程执行安排。
- 采用分阶段交付方式推进 `M0 基线准备`、`M1 MVP 闭环`、`M2 V1 完整能力`。
- 每个阶段均覆盖产品确认、前端实现、后端实现、数据与异步任务、部署安全、质量验证。

### 分阶段边界
- `M0 基线准备`：统一规格、数据模型、仓库结构、基础环境与开发约束（含前端 `pnpm`、Python `uv`）。
- `M1 MVP 闭环`：完成微信登录、家庭与宝宝管理、喂养/排泄/测量/睡眠记录、日报、基础趋势、基础后台和容器化部署。
- `M2 V1 完整能力`：补齐用药、疫苗、里程碑、提醒中心、周报/月报、AI 问答与自动总结、报告导出、H5 分享页。

### 明确不在本任务范围
- 图片/视频附件与 OCR。
- 医生视图、社区、商城、问诊。
- 会员计费、多租户商业化能力。
- 智能硬件同步与深度接入。
- 多语言和复杂国际化支持。

## 交付物
- 可执行的前后端与后台应用代码基线。
- 与设计一致的 API、数据库与异步任务实现。
- 容器化部署配置、环境变量模板、备份恢复手册。
- 自动化测试基础、联调记录和上线验收清单。
- 与规格一致的接口实现和数据库初始化脚本。

## 风险
- `M1` 与 `M2` 涵盖事件类型多，若统一事件模型实现不稳，会导致后续提醒、导出和 AI 全部受影响。
- 汇总重算与趋势快照采用最终一致，若任务补算机制不完善，容易出现前台数据与明细不一致。
- AI 能力必须严格限制为记录解读，若提示词或兜底策略不充分，存在合规和认知偏差风险。
- 导出与分享依赖对象存储和异步任务，若环境准备滞后，会拖慢 `M2` 收尾。

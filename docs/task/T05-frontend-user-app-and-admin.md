## 任务背景
- `D01` 已定义页面树和端能力划分，`D02` 已定义关键流程。
- 需要把这些设计输入转成具体前端执行范围，并明确哪些页面和交互由前端 agent 主责维护。

## 任务范围

### 负责范围
- 微信小程序页面、状态管理和交互流程。
- H5 分享页和报告页前端展示。
- 管理后台页面结构、基础查询页和操作反馈。
- 与 API 的联调适配和前端错误处理。

### 不负责范围
- API 契约和数据库结构变更。
- 后端业务逻辑、权限校验和异步任务实现。
- AI 提示词和模型调用策略。

### 开发约束
- 前端依赖安装、脚本执行和锁文件管理统一使用 `pnpm`。
- 不混用 `npm` 或 `yarn`，避免多套锁文件导致联调环境不一致。

## Agent 执行边界

### 允许维护
- 当前文档 `T05`
- 与前端信息架构、页面流程、联调问题相关的前端说明文档
- 必要时回写 `T10` 中的联调问题条目，但不改其整体验收结论

### 禁止越界
- 不直接修改 `T04` 的契约冻结结论。
- 不直接改写 `T06`、`T07`、`T08` 的后端任务拆解。
- 不以页面便利性为由自行改变后端字段语义。

## 预计输入
- `D01` 中的页面树和端能力划分。
- `D02` 中的关键业务流程和异常分支。
- `T04` 冻结后的 API 契约和字段约束。
- `T06`、`T07`、`T08` 提供的可联调接口能力。

## 预计输出
- 小程序、H5、后台的页面任务和交互落地结果。
- 页面级联调问题清单和待后端配合项。
- 可供 `T10` 验收的前端版本说明。
- 前端页面域交接记录。

## agent 接手说明
1. 接手前确认本 agent 只负责 `T05`，不同时维护后端任务文档。
2. 开始执行时把“当前状态”改为 `进行中`，并在“交接记录”中写明负责页面域。
3. 仅在本任务文档维护页面任务、联调问题和前端待配合项。
4. 若后端接口缺失或契约不稳定，先登记到“外部依赖登记表”，不要直接修改 `T04/T06/T07/T08`。
5. 页面域交接给其他 agent 时，必须在“交接记录”中注明已完成页面、未完成页面和阻塞项。

## 完成标准
- 用户端和后台端页面都有明确的主责边界，不与后端任务文档混写。

- 执行 agent 可以仅维护本任务文档而不需要改写其他任务细节。

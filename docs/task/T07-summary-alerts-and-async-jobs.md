## 任务背景
- 日报、趋势、提醒和异步任务是事件写入后的派生能力。
- 这些能力若与核心事件服务混合维护，容易造成 agent 同时修改同一逻辑区域。

## 任务范围

### 负责范围
- `task_jobs` 调度、领取、重试和失败处理。
- `daily_summaries`、`weekly_summaries`、`metric_snapshots` 的生成和补算。
- 趋势查询依赖的数据准备。
- 提醒规则扫描和 `alert_events` 生成。

### 不负责范围
- 事件主写入和审计落地。
- AI 提示词、导出渲染和分享令牌。
- 小程序和后台页面实现。

## Agent 执行边界

### 允许维护
- 当前文档 `T07`
- 与汇总、提醒、任务调度相关的实现说明

### 禁止越界
- 不改写 `T06` 的登录、家庭和统一事件任务拆解。
- 不改写 `T08` 的 AI 和导出任务拆解。
- 不自行改动 `T04` 已冻结的基础字段定义。

## 预计输入
- `T06` 的事件写入结果和审计基础。
- `T04` 冻结后的实体、表结构和指标字段定义。
- `D06` 中的规则类型和阈值口径。
- `T08` 对聚合结果消费格式的要求。

## 预计输出
- 可运行的任务调度基础设施。
- 日报、周报、趋势快照和提醒结果。
- 供 `T05` 展示、`T08` 消费和 `T10` 验收的派生数据输出。
- 派生链路失败和补算异常记录。

## agent 接手说明
1. 接手前确认本任务只负责派生数据和异步任务，不负责事件主写入。
2. 开始开发时把“当前状态”更新为 `进行中`，并注明当前负责的子域。
3. 所有补算逻辑、规则扫描和任务失败处理都先回写本任务文档。
4. 若发现需要修改 `T06` 的事件契约或 `T08` 的消费格式，先登记依赖，不直接越界。
5. 交接时必须说明当前已稳定的派生链路、已知不一致点和待验证场景。

## 依赖与阻塞

| 类型 | 内容 | 应对方式 |
| --- | --- | --- |
| 主数据依赖 | 事件写入不稳定会导致补算不可信 | 等待 `T06` 基础链路稳定 |
| 规则依赖 | 规则口径和阈值未确认 | 以 `D06` 为准，不自行扩展规则 |
| 性能依赖 | 补算开销可能影响写入后可见性 | 在本任务中记录性能风险，不转嫁给其他任务文档 |
